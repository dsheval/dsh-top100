# v0.2 更新说明

- 更新日期：2026-08-25
- 基线分支：`main`
- 目标分支：`v0.2`

## 概览

v0.2 在原有数据采集、SQLite 存储和静态网页版之外，新增了可独立发布的 DeepSeek Harness 插件。用户只需安装插件即可在 DSH 设置页浏览和安装榜单项目，不需要下载 Collector、数据库或网页版后端。

插件与网页共用公司服务器发布的 `rankings.json`，因此榜单、分类和更新时间来自同一份数据快照。

## 相对 main 的主要变化

### 独立 DSH 插件

新增 `plugin/` workspace，包含 Host 和 Client 两端：

- 在 DSH 设置页展示 Top 100、新锐榜、总榜和分类榜。
- 网页与 DSH 插件共用同一套加权搜索核心：名称、仓库名、标签、topics 和简介分级计分，支持自然语言停用词、中英文同义词、轻度拼写纠错和相关度排序，同时保留原始榜单名次。
- 支持单个安装和最多 20 项的批量安装。
- 展示排队、验证、下载、等待 Profile、安装、完成、失败和取消状态。
- 支持取消失败任务和重新安装。
- Cordis 插件写入当前 DSH Profile；Skill 安装到 DSH skills 目录。
- 数据源可以通过插件配置或 `DSH_TOP100_DATA_URL` 覆盖。

插件源码按职责拆分：

```text
plugin/src/
├── index.ts          # 插件入口与 DSH 注入
├── host/             # 数据获取、Profile、设置和 HTTP API
├── install/          # 安装解析、执行、校验与 Skill 安装
├── client/           # DSH 设置页界面
└── shared/           # Host/Client 共用的数据类型和分类契约
```

### 分类统一

Collector、网页版和 DSH 插件统一为六个受控分类：

1. Agent增强
2. 外观
3. 编程
4. 知识获取
5. 工具
6. 安全

DeepSeek 根据 README、描述和 topics 选择一个主分类，并补充一至两个有明确依据的相关分类。规则回退同样限制为最多三个分类，并使用单词边界降低关键词误判。

插件优先读取 `rankings.json.categories` 中的分类名称、说明和数量，同时使用每个榜单条目的 `categories` 字段进行筛选。内置六分类仅用于兼容旧数据，避免网页和插件分别维护不同的业务分类。

### Collector 和数据质量

- 删除旧的通用中文占位简介，避免把无具体含义的文案继续写回缓存。
- DeepSeek 中文简介提示词要求描述仓库独有能力和用户收益。
- 模型不可用时，根据仓库名称和原始描述生成更具体的回退简介。
- 分类缓存写入数据库前统一进行标准化。
- 更新 `data/plugins.json` 中的插件、简介和分类数据。

### 网页更新

- 分类入口由九类收敛为六类，与插件保持一致。
- 调整分类布局、标题排版、响应式显示和首屏动效。
- 增加 README 封面页面和 dsheval Logo 设计资源。

## 数据流

```text
GitHub / npm / curated sources
              │
              ▼
          Collector
              │
     DeepSeek 简介与分类
              │
              ▼
      SQLite + rankings.json
              │
      公司服务器静态发布
              │
       ┌──────┴──────┐
       ▼             ▼
  www.dsheval.ai 网页   DSH 插件 Host
                         │
                         ▼
                    DSH 设置页 Client
```

浏览器端不会直接访问榜单服务器。DSH 插件 Host 拉取并缓存远端 JSON，再通过本机 `/dsh-top100/*` 接口提供给设置页。

## 插件接口

| 接口 | 用途 |
|---|---|
| `GET /dsh-top100/status` | 插件版本、数据源、Profile 和活动任务 |
| `GET /dsh-top100/rankings` | 排行榜、搜索、分页和分类筛选 |
| `GET /dsh-top100/installed` | 当前 Profile 已安装项目 |
| `GET /dsh-top100/install-jobs` | 批量安装任务状态 |
| `POST /dsh-top100/install-batch` | 创建批量安装任务 |
| `POST /dsh-top100/cancel` | 取消安装任务 |
| `POST /dsh-top100/retry` | 重试失败或取消的任务 |
| `POST /dsh-top100/cancel-all` | 取消全部活动任务 |

所有改变本地状态的接口都要求同源 POST。

## 安装安全边界

- 安装目标必须来自当前榜单条目，不能提交任意 shell 命令。
- 不执行 README 中记录的安装命令。
- npm 包名、GitHub 仓库名和 Profile 名都经过格式校验。
- Git 来源在安装前校验仓库身份、package manifest 和 DSH bundle 声明。
- 只有用户确认的精确包名可以写入 `allowBuilds`。
- 同一 Profile 的写入操作串行执行，避免多个 pnpm 进程同时修改依赖。
- Skill 安装拒绝符号链接，只复制包含合法 `SKILL.md` 的目录。

## 独立发布范围

执行 `npm pack -w dsh-top100-plugin` 时，发布包只包含：

- 编译后的 Host 代码 `lib/`
- 浏览器端代码 `client/client.js`
- `cordis.patch.yml`
- 插件 `package.json` 和 README

本次 dry-run 结果约为 24.7 KB、32 个文件，不包含 `collector/`、`data/`、SQLite、Docker 配置或 `web/`。

## 部署前检查

默认数据地址为：

```text
https://www.dsheval.ai/data/rankings.json
```

正式发布前必须确认该地址返回 `application/json`，并包含 `rankings.total`、`rankings.hot`、`rankings.rising` 和 `categories`。如果生产域名尚未完成路由，可临时通过 `DSH_TOP100_DATA_URL` 指向正确的数据目录。

开发环境安装方式：

```bash
npm run plugin:build
dsh plugin --profile web add link:/absolute/path/to/dsh-top100/plugin
```

安装后重启 `dsh web`，在“设置 → 插件排行”中验证榜单、分类和安装流程。
